# Z-Girl v3.8 Governance Calendar Standard

## Purpose
Create a repeatable institutional governance rhythm across access recertification, evidence review, annual closeout, SSO review, offboarding, license renewal and credential-capacity checkpoints.

## Authority model
Automation may:
- open a configured annual review window;
- create a draft annual review cycle and calendar item;
- register existing v3.7 governance evidence for periodic administrative review;
- flag calendar and retention items as due.

Automation may not:
- change operator roles or sessions;
- delete governance evidence;
- finalize a governance report;
- record an attestation;
- generate authority for an audit package;
- issue or renew a credential;
- activate, renew or expand a license;
- execute an agreement or release implementation;
- change payment or revenue state.

## Annual closeout
A completed annual cycle requires all three evidence objects from the same institution:
1. finalized governance report;
2. attested access-governance record;
3. audit package.

After those objects are linked, the cycle becomes ready to close. System Owner closeout remains a separate human action.

## Tenant scope
Governance-calendar reads and ordinary administrative actions inherit the existing v3.5/v3.6 named-operator and institution-scope controls. System Owner authority remains required for final disposition/closeout actions.

## Data boundary
The governance calendar contains administrative metadata only. Participant private reflections, youth/student/athlete case records, diagnosis/treatment information, counseling notes, safeguarding narratives, clergy/spiritual-direction records, sports-medicine records, credential assessment answers/scores and practicum detail are excluded.
