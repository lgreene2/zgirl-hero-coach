# Z-Girl v3.11 — Institutional Pilot Engine

## Product role

The Institutional Pilot Engine is the reusable implementation layer that turns a qualified institutional relationship into a governed Z-Girl deployment, evidence cycle and renewal/expansion pathway.

It is configurable across schools, districts, colleges/universities, nonprofits, youth-serving organizations, faith organizations, athletic programs, municipalities, community organizations and other approved institutional partners.

## One engine, configurable profiles

Institution profile controls the implementation context. Solution profile controls approved Z-Girl content/configuration. Neither changes the participant privacy boundary.

Supported solution profiles include General, EDU, Faith, Athlete and Accessibility Support.

## Core operating objects

- Institution Record — existing Z-Girl tenant entity
- Named Operator / RBAC — existing identity system
- Pilot Program — implementation lifecycle and GLS references
- Intake — qualification/readiness and implementation requirements
- Team Assignment — adult operational responsibilities; does not itself grant access
- Cohort — aggregate participant structure/capacity
- Milestone — onboarding/implementation checkpoint
- Metric Snapshot — aggregate implementation counts
- Evidence Record — provenance-labeled implementation/outcome evidence
- Permission Record — testimonial/case-study/reference/funder-use status
- Competency Signal — evidence for future facilitator standards/training
- Closeout — implementation summary and renewal/expansion recommendation
- Event — administrative audit history

## Institutional lifecycle

Opportunity → Qualified → Agreement/Scope → Institution Setup → Onboarding → Pilot Ready → Live → Evidence Collection → Completed → Renewal → Expansion

The database enforces prerequisite gates. On Hold/Cancelled are explicit exceptional states rather than shortcuts.

## Administrator experience

The Pilot Command Center gives executives/operators a readable portfolio view with stage, readiness, blockers, next actions and evidence status.

Each pilot workspace exposes:
- institutional profile and GLS linkage
- intake/readiness
- operational team
- cohorts/capacity
- milestones
- aggregate implementation evidence
- facilitator-learning backlog
- closeout and next-stage decision
- commercial/SOW packet
- evidence package
- publication/reference permissions

## Privacy model

The implementation engine does not require individual participant names/emails in the institutional admin layer. Reflection usage is represented as aggregate session/activity counts. Private reflection text remains participant-controlled and outside institutional reporting.

## Commercial model

GLS owns opportunity/proposal/agreement/invoice/payment/relationship state. Z-Girl stores enough administrative scope metadata to implement the engagement and create institution-ready SOW/evidence packets without becoming a duplicate CRM.

## Pilot-to-case-study model

Implementation evidence is captured once with provenance and permission metadata, then can support approved derivatives: executive brief, case study, testimonial, institutional reference, grant/funder evidence, renewal/expansion proposal and facilitator-training source material.

## Pilot-to-Train-the-Trainer model

The pilot does not issue new facilitator credentials. It captures the implementation learning needed to make later facilitator standards defensible: safeguarding, escalation, platform administration, reflection facilitation, accessibility/adaptation, institutional communication, evidence/reporting, fidelity and implementation planning.
